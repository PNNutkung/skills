# qa-sweep Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the `qa-sweep` skill (find defects, weak tests and test gaps with proofs checked in code, write regression tests into the existing suites), plus the `qa-guard` hook, the removed-test check and inventory in `pr-test-tiers`, and whole-file mutation in `zero-trust-review`.

**Architecture:** Approach A from the spec: one skill run in the user's session. A short router `SKILL.md` and one markdown file per mode guide the agent; small plain-code scripts (`run.mjs`, `pairwise.mjs`, `findings.mjs`, `target.mjs`) produce and check every fact. Enforcement lives in hooks: `qa-guard.mjs` (tests only, no commits, during a run) and `pr-test-tiers.py` (removed-test check at change-request time).

**Tech Stack:** Node 18+ ES modules with `node:test`; Python 3 standard library; git. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-19-qa-sweep-design.md`

## Global Constraints

- Node 18+ and Python 3 only; no new dependencies (spec: "No new dependencies").
- Backward compatible: new flags, exports and subcommands only; every existing default and output stays as it is.
- Node tests: `node --test <file>.test.mjs`, in the style of `skills/zero-trust-review/mutate.test.mjs` (fixture git repos in `mkdtempSync(tmpdir())`, stub runners, no real sandbox).
- Python hook tests: inside `self_test()`, run with `python3 hooks/pr-test-tiers/pr-test-tiers.py --self-test`.
- Named constants for every threshold: `FULL_MAX = 50` (pairwise), `IDLE_MS = 2 * 3600e3` (run marker idle expiry).
- Hooks fail open: any internal error means exit 0 with no output.
- Lint and format only the files you changed, never the whole repo.
- Commit messages: one line, one sentence, `<type>: <description>`. A local hook rejects a body or a second `-m`.
- `SKILL.md` frontmatter `description` is a double-quoted string (commit 9d9c968: an unquoted one made `skills add` skip the skill).
- The repo is public: no company-internal names, hosts or tools in any file.

## Review Focus

1. A test file whose path has a space or non-ASCII characters is deleted: the removed-test check must still see it (`-z` output, `core.quotepath=off`). Test in Task 3.
2. A hook input that is not JSON, or has no `tool_input`, `session_id` or `cwd`: `qa-guard` allows the action, prints nothing and exits 0. Test in Task 5.
3. An existing test file with CRLF line endings is rewritten with an appended test: the additive check compares lines with a trailing `\r` stripped, so this counts as additive. Test in Task 5.
4. A `--files` line range that runs past the end of the file: the range is clamped to the file's length, not an error and not out-of-range mutants. Test in Task 1.
5. A target URL that only looks local (`http://localhost.evil.example`, `http://127.0.0.1.nip.io`) is refused, while `http://[::1]:8080` and `http://LOCALHOST.:3000` are local. Test in Task 8.

### Task 3: Removed-test check in `pr-test-tiers`

**Files:**
- Modify: `hooks/pr-test-tiers/pr-test-tiers.py` (`evaluate` at 251-275, `judge` at 278-295, new helpers, docstring)
- Modify: `hooks/pr-test-tiers/README.md`
- Test: `self_test()`

**Interfaces:**
- Consumes: `_git`, `is_test`, `load_cfg`, `parse_added` (existing).
- Produces:
  - `SKIP_PATTERNS`, a list of regexes. Skips: `@pytest\.mark\.skip\b`, `\bpytest\.skip\(`, `@unittest\.skip`, `\b(?:it|test|describe)\.skip\(`, `\bx(?:it|test|describe)\(`, `\bt\.Skip(?:Now|f)?\(`, `@Disabled\b`, `@Ignore\b`. Expected-failure markers, which silence a failing test just as well: `@pytest\.mark\.xfail\b`, `\bpytest\.xfail\(`, `@unittest\.expectedFailure\b`, `\b(?:it|test)\.(?:fails|failing)\(`, `\btest\.fail\(`.
  - `SKIP_MARKER = re.compile(r"skip-reason:\s*\S+")`.
  - `TRAILER = re.compile(r"^Test-Removed:\s*(.+?):\s*\S", re.M)`.
  - `PY_TEST_DEF = re.compile(r"^\s*(?:async\s+)?def\s+(test_\w*)\s*\(")`, matching the Python half of `test-name-guard`'s `PY_DEF`.
  - `JS_TEST_CASE = re.compile(r"\b(?:it|test)(?:\.only)?\s*\(\s*(['\"`])(.+?)\1")`.
  - `parse_removed(diff_text: str) -> dict[str, list[str]]`: `{path: [removed lines]}`, keyed by the `--- a/` path.
  - `removed_tests(root: str, base: str, cfg: dict, extra: list | None) -> list[tuple[str, str]]`: `(path, what)` for each uncleared removal. `what` is one of `"deleted test file"`, `"removed test <name>"`, `"added skip or expected-failure marker: <line[:80]>"`.
  - `evaluate(...)` returns a new key, `"removed"`, computed **before** the early `exempt` return, so a diff that only deletes tests is still checked.
  - `judge(...)` reports `removed` even when `exempt` is true. It denies for `pr` and adds context for `commit`.
- Rules (from the spec):
  - A deleted test file comes from `git diff --name-status -z --find-renames base...HEAD`. Renames are not deletions.
  - A test name counts as removed when it appears in removed lines of a test file and in no added line anywhere in the diff, so a test moved to another file passes.
  - A skip is an added line in a test file matching `SKIP_PATTERNS`, unless `SKIP_MARKER` is on the same line or the line before it, in the new file content.
  - A deleted file or a removed name is cleared by a `Test-Removed: <path>: <reason>` trailer in any commit message of `git log base..HEAD --format=%B`.
  - A rename of a test function within one file counts as a removal. It is not detected as a rename (the spec leaves this to the builder; YAGNI). It needs a trailer.

- Produces (exports):
  - `IDLE_MS = 2 * 3600e3`.
  - `markerDir(env = process.env): string` returns `env.QA_MARKER_DIR || join(userInfo().homedir, '.cache', 'qa-sweep')`. `QA_MARKER_DIR` is a test seam, like `ZT_MARKER_DIR`.
  - `markerPath(session: string, env?): string` returns `join(markerDir(env), `${session}.json`)`. `session` must match `/^[A-Za-z0-9-]{1,80}$/`, else it throws `bad session id`.
  - `start({ repo, session, env, now, uid }): { run: string, marker: string }`. It creates the run dir `qa-<ISO timestamp with : replaced by ->` and writes the marker `{"run", "session", "repo", "started"}` (repo = realpath of `git rev-parse --show-toplevel`) with mode 0600 and flag `wx`. It throws `a run is active: <run>` when this session's marker is fresh, and replaces a stale one.
  - `readActive({ session, env, now, uid }): { run, session, repo, started } | null`. It returns null when the marker is missing, older than `IDLE_MS` by mtime, a symlink, not a regular file, not owned by the user, group- or world-writable, not valid JSON, or names a run dir that fails `checkRunDir`. These are the same checks as `runctx.mjs` `readMarker`; a comment points there.
  - `touch({ session, env }): void` updates the marker's mtime when this session's run is active, and otherwise does nothing.
  - `end({ session, env }): { ended: string | null }` removes this session's marker. It is idempotent.
- Produces (CLI): `node run.mjs start --repo DIR [--session ID]`, `node run.mjs end [--session ID]` and `node run.mjs touch [--session ID]`. The session defaults to `process.env.CLAUDE_CODE_SESSION_ID`; with none, exit 2 with `no session id: pass --session`. Each prints one JSON line and exits 0, except usage errors and an active run on `start`, which exit 2.

### Task 5: `qa-guard` hook

**Files:**
- Create: `hooks/qa-guard.mjs`
- Modify: `hooks/hooks.json` (add a PreToolUse entry with matcher `Edit|Write|Bash`, command `node "${CLAUDE_PLUGIN_ROOT}/hooks/qa-guard.mjs"`, timeout 5)
- Test: `hooks/qa-guard.test.mjs`

**Interfaces:**
- Consumes: `readActive({ session, env })` and `markerDir` from `../skills/qa-sweep/run.mjs` (Task 4). `python3 <root>/hooks/pr-test-tiers/pr-test-tiers.py --is-test PATH` (Task 2) decides what a test file is. If it exits with anything other than 0 or 1, fail open.
- Produces: the hook. It reads one JSON object `{ session_id, cwd, tool_name, tool_input }` from stdin, and prints either nothing (allow) or `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason": <text>}}`.
- Also exports pure functions for the tests: `isAdditiveEdit(oldString: string, newString: string): boolean`, `isAdditiveWrite(oldText: string, newText: string): boolean` (old lines are an ordered subsequence of the new lines, with a trailing `\r` stripped), and `bashVerdict(command: string, ctx): string | null` (a deny reason, or null).
- Decision order, from the spec:
  1. No `session_id`, no active run for it, or the target's repo (git toplevel of `tool_input.file_path`'s directory, or of `cwd` for Bash) is not the marker's `repo`: allow.
  2. Bash: a command containing `qa-sweep/run.mjs end` is always allowed. Otherwise deny when any segment (split on `;`, `&&`, `||`, `|`, `&` and newline, with env assignments and `git` global flags `-C X` / `-c K=V` stripped) is `git commit` or `git push`. Best-effort, deny an output redirect (`>`, `>>`), `tee FILE` or `sed -i ... FILE` whose target is not a test file and not inside the run dir.
  3. Edit or Write inside the run dir: allow.
  4. Edit or Write to a non-test file: deny.
  5. Edit to an existing test file: allow if `isAdditiveEdit`. Write to an existing test file: allow if `isAdditiveWrite` against the file on disk. A new test file: allow.
- Deny text: `qa-sweep run <run> is active in this session: <why>. During a run only test files (additions only) and the run folder may change, and nothing is committed. To end the run: node <absolute path to skills/qa-sweep/run.mjs> end`
- Fail open: wrap everything. On error, exit 0 with no output, and append the error to `<run>/hook-errors.log` when the run is known.

### Task 6: `pairwise.mjs`

**Files:**
- Create: `skills/qa-sweep/pairwise.mjs`
- Test: `skills/qa-sweep/pairwise.test.mjs`

**Interfaces:**
- Produces:
  - `FULL_MAX = 50`.
  - `pairwise(params: Record<string, unknown[]>, { fullMax = FULL_MAX } = {}): Array<Record<string, unknown>>`. When the product of the value counts is at most `fullMax`, it returns the full product. Otherwise it returns a set in which every pair of values from two different params appears in some row. The output is deterministic: no randomness, keys in input order. It throws `params must be a non-empty object of non-empty arrays` on bad input.
  - CLI: `node pairwise.mjs FILE.json` prints the JSON array. It calls `touch()` from `run.mjs` (Task 4) with `process.env.CLAUDE_CODE_SESSION_ID`, ignoring errors.
- Algorithm (greedy, since the tests do not determine one): while uncovered pairs remain, build one row param by param, choosing for each the value that covers the most uncovered pairs with the values already chosen in that row. Ties go to the first value. Then remove the row's pairs.

### Task 7: `findings.mjs`, the proof checker and the report

**Files:**
- Create: `skills/qa-sweep/findings.mjs`
- Create: `skills/qa-sweep/fixtures/` (a findings JSON, a ledger, an answers file)
- Test: `skills/qa-sweep/findings.test.mjs`

**Interfaces:**
- Consumes: `checkRunDir`, `writeSafe` from `runctx.mjs` (located as in Task 4); `touch()` from `run.mjs`.
- Input file (`--findings FILE.json`), written by the agent:
  ```json
  { "requirements": [{ "id": "R1", "text": "…", "source": { "kind": "spec|ticket|user", "ref": "docs/x.md:12 | <url> | A3", "quote": "…" } }],
    "findings": [{ "id": "F1", "kind": "defect|weak-test|test-gap", "requirement": "R1", "tier": "unit|integration|e2e", "title": "…",
                   "proofs": [{ "mode": "code|executed", "ref": "path:line | <run id>", "quote": "…", "exit": 0, "coverage": false }] }],
    "tests_written": [{ "path": "tests/unit/test_x.py", "finding": "F1", "proofs": [ … ] }],
    "unconfirmed": [{ "question": "…", "behavior": "…" }] }
  ```
- Ground truth, as files in the run dir: `exec.jsonl` (the runner ledger: one JSON per line, `{id, exit, out, backend, cmd}`), `answers.md` (user answers, one `A<n>: <verbatim answer>` block each), `ticket.md` (ticket text, verbatim). Each is read only after `checkRunDir(run)` passes and the file is a regular file owned by the user, not a symlink and not group- or world-writable. These are the same checks `proofcheck.mjs` uses on its ledgers; a comment points there.
- Produces (exports):
  - `checkProof(proof, ctx): { ok: boolean, reason?: string }`.
    - A `code` proof passes when `quote` (whitespace-normalized) appears in the file at `ctx.head` within ±2 lines of `ref`'s line.
    - An `executed` proof passes when the ledger has `ref`, its `backend` is one of `direct`, `seatbelt`, `bwrap` or `docker`, `exit` matches when given, and `quote` is in its `out`.
  - `checkSource(requirement, ctx): { ok, reason? }`. `spec` works like a `code` proof. `ticket` passes when `quote` is in `ticket.md`. `user` passes when `quote` is in the `A<n>` block named by `ref`.
  - `checkFinding(finding, ctx): { ok: boolean, reasons: string[] }`. The requirement's source must check out, and there must be:
    - test-gap: an `executed` proof whose quote matches `/^ZT-MUTANT \S+ \S+:\d+ \S+ exit=0$/`, or an `executed` proof with `coverage: true` when `tier` is `e2e`.
    - weak-test: a `code` proof plus a surviving-mutant `executed` proof.
    - defect: an `executed` proof with `exit !== 0`.
  - `checkWritten(entry, ctx)` requires an `executed` proof with `exit: 0` (it passes on HEAD) plus an `executed` proof matching `ZT-MUTANT … exit=<non-zero>` (it kills the mutant).
  - `renderReport(data, verdicts, inventory?): string` produces markdown with the sections in this order: Inventory (only when given), Requirements, Defects, Weak tests, Test gaps, Tests written, Unverified (each failed item with its reasons), Unconfirmed. Empty sections are left out, but Unverified and Unconfirmed always appear when they have entries. Every input item appears in exactly one section.
  - CLI: `node findings.mjs --run DIR --repo DIR --head REV --findings FILE [--inventory FILE] [--out FILE]`. It writes the report (default `<run>/report.md`) with `writeSafe`, prints `{report, verified, unverified, unconfirmed}` as JSON, and exits 0. Usage errors exit 2.
