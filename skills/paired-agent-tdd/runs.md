## Measured, 2026-10-08 (the rewrite on top of the old graph)

- **Fixed cost per agent type** (Agent tool, one `echo ok` task each, all-in subagent tokens): general-purpose 98,078; code-reviewer 41,261; tdd-guide 38,189; code-simplifier 37,490. A narrow agent type costs about 2.4x less before it does any work, and the judges (code-reviewer) also lose Edit and Write. Drivers, fixer and integration tester use `tdd-guide`; navigators and the reviewer `code-reviewer`.
- **Skill text loaded per invocation:** `SKILL.md` 22,038 bytes before, 13,032 after; the rules moved into briefs the script writes (`workflow.js` prompts are 0.9-1.8 KB each) and into `probes.md` / `tiering.md`, read on demand.
- **Offline proofs, no model:** 37 unit tests for the gates and plan validation (`gates.test.mjs`, `tdd.test.mjs`), 15 scenarios for `workflow.js` with canned agents (streaming without a barrier, the `after` edge, bounded rework, the matrix checked in code, one fixer per owning group, the pool of 6, retry, determinism for resume), and `e2e.test.mjs`: the real `workflow.js` and the real gates in a fixture repo with scripted agents, once with a stub runner and once in the **real seatbelt sandbox** (`E2E_REAL=1`). The end-to-end run exercises: `plan`, RED gate, GREEN gate that **refused weak tests because a mutant survived**, a strengthening pass, the `--retest` re-check, a reviewer finding with a `read` proof, a fixer, `verify` (DoD 8/8 pairs, finding gone, proof confirmed against the tree the reviewer saw), and the user's repo untouched (no commit, no ref).
- **Bugs those tests caught before any real run:** (1) a dependent group's snapshot was a sibling of its base, so the probes' `base...head` merge-base diff dragged the other group's files into its change and mutated them; fixed by making it a child (unit test `a dependent group is judged on its OWN code`). (2) A `mktemp -d` run folder is not approved by `sandbox-run` or `proofcheck` (explicit run dirs must live under the per-user `zt-review-<uid>` base), so the ledger and the proof checks would silently have been off; fixed with `createRunDir` in `runctx.mjs` (no marker, so the review-only guard hook does not restrict the code-writing agents).

- **Independent review of the first version** (a read-only code-reviewer agent, 228k tokens, 29 tool calls, ~16 min) found 10 substantiated defects that all offline tests had missed; each is fixed with a test: (1) the DoD closure credited rows no test backed (`ac10` serving `ac1`, one test listed for three kinds, an empty name); (2) a nit blocked `done` forever; (3) the integration test was never gated; (4) the closure ignored flaky and changed-since-RED groups and credited tests written after GREEN; (5) the prompt allowed `git stash`/`checkout` while six agents share one tree; (6) a stray file made by one group blocked another group's gate; (7) the fixer fence for out-of-plan files came from the reviewer's free text, and the strengthen prompt told the driver to write failing tests; (8) a `src` file the probes never count as source made a group unable to go green; (9) non-ASCII paths were quoted by git and read as stray; (10) a repo that is a subdirectory of a work tree broke the snapshots (RED `ok` for a test that never ran). It also found scratch trees never deleted, a moving `base`, and a stale review marker silently putting the guard on the code-writing agents.

## Measured, 2026-10-09 (the repair loop: every stage edits, runs the real gate and edits again)

- **Offline proofs, no model:** 60 node tests (gates 24, `tdd` 32, record 4), 20 scenarios for `workflow.js` with canned agents (rounds and the cap, the stall check, a PASS that admits `gateOk=false`, restore versus strengthen, `--retest` only after a strengthening, fixers in `after` order, the courier and its fix passes, the ceiling of 5 + 5R build agents reached by a navigator that never passes), and `e2e.test.mjs` with the real gates, once with a stub runner and once in the **real seatbelt sandbox**: group a's drivers loop on the real gate and `dod` commands from their own prompts, group b's lazy first GREEN pass is refused by the real gate and repaired, a fixer re-runs its group gate, the courier re-runs `final --again`, and `verify` still reads 8/8 DoD pairs and a confirmed proof against the tree the reviewer saw.
- **Mutation probe on the new code (dogfood):** `gates.mjs` 22 of 22 killed after closing 6 gaps it found in my tests (the `rounds` bounds, two `parseRow` edges); `workflow.js` 42 of 60 at first, 82 of 90 after the fixes, and the 8 survivors are config values (a call cap, the pool size), a clip length and a promise value no caller reads; three more were pinned afterwards and not re-measured. `tdd.mjs` is outside the sandboxed probe (its tests need git and temp dirs: `unverifiable`), so a hand-run pass killed 25 of 28 mutants on the new code; the 3 survivors (an unreadable-row count that also fired for phantom rows, two exit codes) were fixed or pinned and not re-measured.
- **Defects found before any real run:** the Converge phase dropped the first round's fixer records (scenario test); then an independent read-only review (a code-reviewer agent, 216k tokens, 38 tool calls, ~13 min; no critical or high) found 4 medium defects, all fixed with tests: a maker's gate ran without `--retest` after a strengthening round and failed on the sanctioned edit; a changed frozen test was handled like a surviving mutant and so switched off the frozen-tests check; the stall key ignored the line and cut the text at 60 characters, so progress could read as a stall and block a group and its dependents; fixers of dependent groups ran their gates against a half-edited dependency. It also corrected the ceiling (5 + 5R per group, not 4 x (1 + R)), a prompt contradiction in the two-maker case, and "two rounds" of Converge, which was one fix pass.
- **Known limits of the new part:** a failure the courier traces to another group's code goes to the owner of the failing file, whose fence may not reach the cause (it reports `notFixed`, the run lists it under `notDone`); a reworded defect is not seen as the same one, so a stuck group spends its rounds instead of stopping early.

## Measured, 2026-10-09 (continue after a failure, and spend less when one happens)

- **What the new design does when an agent fails or a group will not pass:** a plain-code `tdd.mjs resume` (no agent, no tokens) reads the gate files and writes `continue.json`; the next Workflow run carries finished groups over for free and restarts the others at the stage they stopped, with the defects the gates and the last navigators reported; a run-wide repair budget (`maxRepairs`, default 2 per group, a fair share kept for each) pauses a group instead of retrying it; a maker that stops on a failing gate says what remains, so no navigator is paid to find a failure that is already known; a paused run is not reviewed until it is whole.
- **Offline proofs, no model:** 71 node tests (gates 27, `tdd` 40 with 8 for resume, record 4), 26 `workflow.js` scenarios (budget and pause, admissions, every `next` entry point of the continue file, fair shares, carried groups outside the budget, no review while paused, a continue file refused for another base or run), and `e2e.resume.test.mjs` with the real gates, with a stub runner and in the **real seatbelt sandbox**: run 1 has no repair budget and a lazy GREEN pass so the group is paused after 4 agents; `tdd.mjs resume` writes the continue file; run 2 spends **3 agents** (one repair, one check, the review) and the DoD still closes 3/3.
- **Mutation probe on the new code (dogfood):** `workflow.js` 120 of 130 killed (the survivors are config values, a pool size, and branches no caller can tell apart; 3 fairness boundaries were pinned afterwards and not re-measured); `gates.mjs` 22 of 22 after pinning 2; `tdd.mjs` (hand-run: its tests need git and temp dirs, which the sandboxed probe reports as `unverifiable`) 39 of 41, the 2 survivors (de-duplication of merged rows and defects) pinned afterwards and not re-measured.
- **Agents for one group whose GREEN check never passes** (measured on the script by an independent reviewer, not on a model): the previous commit 10 build agents and `blocked`; now 5 with the default budget and admissions, 8 without admissions; with the budget raised to 40, 6 and 10. This is a script count, not a token or cost-unit measurement.
- **Found by the independent review before any real run (all fixed with tests):** a resume that ignored what the last navigator said and so could carry RED as passed with no navigator ever passing it; `retest` lost for a group that did not finish; the default budget counting groups already done; a hard group starving an easy one; the opus review running on a paused (partial) run and again after the resume; `rows.json` overwritten by a partial or phantom call; a flaky run classed as a test defect that the restore maker cannot fix; a pruned gate snapshot crashing the whole `resume`; a continue file bound to its base only.
- **Known limits:** a failure the courier traces to another group's code still goes to the owner of the failing file. (A stalled group resuming into the same repair, and an `unverifiable` or `timeout` gate being only a warning, were limits here; the section below closes them.)

## Measured, 2026-10-09 (a stalled group, a broken sandbox and the budget of a continued run)

- **What changed:** `tdd.mjs resume` puts a group whose same defects stalled the last run on `hold`, and one whose gate says `unverifiable` on `env`: both cost no agent until the lead decides (`--retry`, `--hint G=text`, `--escalate G` = one opus maker, or a fixed sandbox). The lead's `--max-repairs N` (default 2 per group that still works) is written to `continue.json` and the Workflow uses it instead of the plan's `maxRepairs`, so a plan value of 0 can no longer pause a continued run at once. `plan` proves the sandbox before anything else (preflight: a test that passes at the base must pass through it), refuses with no sandbox, and a navigator or maker that sees `unverifiable` reports class `env`: the group is `paused` with no repair spent and nothing is reviewed. Exit 127 (the command cannot start) is `unverifiable`, never a RED.
- **Offline proofs, no model:** 82 node tests (gates 28, `tdd` 50, record 4), 27 `workflow.js` scenarios, and both end-to-end tests with a stub runner and in the **real seatbelt sandbox**; the resume one now starts from a base that holds a passing test, so plan's preflight runs it for real, and run 2 spends **3 agents** with the plan's own `maxRepairs: 0` still in the args (the continue file sets the budget). The new scenarios fail on the previous `workflow.js`.
- **Independent review before any real run:** 6 findings (1 high, 3 medium, 2 low), each confirmed against the code and fixed with a test: preflight picked empty `__init__` and `conftest` files and refused healthy repos; a hanging implementation was sent to `env` because the GREEN probe says a timeout as `unverifiable (timeout)`; a hold survived a hand edit whose gate was re-run (it now lifts when any group file is newer than the saved return); `env` and `hold` groups did not stop the opus review; exit 127 was `unverifiable` at RED only.
- **Mutation probe on the new code (dogfood):** `gates.mjs` 9 of 9; `workflow.js` 36 of 39, the 3 survivors are changed clip lengths; `tdd.mjs` 59 of 70, then 66 of 70 after pinning 8, and one of the last 4 (the exit-127 relabel) pinned and killed on the whole suite. The 4 survivors of the second pass: 2 equivalent (a default that is never read, a constant in the empty-file flag), the repeated `--retry` flag (pinned, not re-run) and that relabel.
- **Not measured:** how many tokens `hold` and `env` save in a real run (by script count a held or env group costs 0 agents where a repeated stalled repair costs a maker and a navigator); how often a hold is wrong; whether `--escalate` changes real agent routing (the stub shows `model` and `effort` reaching `agent()` and no more); a real project whose smallest tests cannot pass in the sandbox (`plan.smoke` and `--skip-preflight` are the ways past).
- **Known limits:** preflight proves the command starts and a real test passes, not that every import resolves; the hold reads file modification times against the saved return, so `git checkout` lifts it (the cheap direction); `--hint`, `--retry` and `--escalate` are not remembered between `resume` runs; a shell test whose last command is a not-yet-written script exits 127 and reads as environment.

## Changed, 2026-10-09 (no sandbox by default, config files as group src)

- **What changed:** the gates run the test command through `direct-run.mjs` (no confinement: your rights, network and environment; the same `ZT-RUN` ledger, so `proofcheck.mjs` still verifies `executed` proofs) unless the plan says `sandbox: true`, which selects the zero-trust-review sandbox as before. `plan` refuses only when the chosen runner does not start. A group's `src` may hold config or data files (only a test-like path is refused): the GREEN probe takes `--src` and reverts them like code, the mutation probe leaves them alone.
- **Offline proofs, no model:** 89 node tests here (gates 29, `tdd` 52, record 4, `direct-run` 4) and 63 in `zero-trust-review` (one new for `testprobe.mjs --src`), 27 `workflow.js` scenarios, and both end-to-end tests now run through the real direct runner and, with `E2E_REAL=1`, the real seatbelt sandbox. A group whose only source is `config/alpha.json` reaches `exercises-change` and a GREEN gate that is ok.
- **Not measured:** a real project with a config-only group on a real model run; mutation probe on this change (not run); what an unconfined gate does to a repo whose tests write outside the scratch copy.
- **Known limits:** with the default runner a test can reach your network and files, and a hanging command is stopped by the timeout only; `ro` is ignored unless the sandbox is on; config files are not mutated, so a config-only group has no mutation evidence; the harness hooks and permissions of your own Claude Code setup are not part of this skill and were not touched.

## Estimates, not measurements

- Agents for a 3-group change with one group getting findings, when every first pass is right: 15 (`graph.mjs --plan 3 0 1`: 12 build + reviewer + fixer + the final courier); the old graph for the same change about 27 (1 auditor + 6 per group + integration + 3 dimension reviewers + ~4 fixers; its own counts were never logged). Agent hops on one group's critical path: 6 (7 with an integration test) against 8 (9 with the graph-planner), **+2 per repair round** and +2 when the final courier sends a problem back.
- The repair loop makes the count a **range**: without a run-wide limit the ceiling for the same change is 60 build agents (3 groups x (5 + 5 x 3 rounds), reached by a script test with a navigator that never passes); with the default budget (`maxRepairs` 2 per group) it is 4 x 3 + 3 x 6 = 30, plus the reviewer, fixers, up to 3 couriers and retries. A group that is still failing then is paused and continues from `continue.json` (done groups cost nothing). Where a real change lands between 15 and 30 is the first thing the on-job lines below will show.
